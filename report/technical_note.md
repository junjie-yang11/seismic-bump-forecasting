# Does random cross-validation overstate the skill of seismic-bump forecasting models?

**A leakage study on the UCI Seismic Bumps dataset**

Technical note · all numbers generated by `run_experiments.py`

---

## Abstract

Machine-learning results on the UCI Seismic Bumps dataset — shift-level records from a
Polish coal mine, where the task is to forecast whether a hazardous seismic event will
occur during the *next* shift — are commonly reported under stratified *k*-fold
cross-validation. Because the records form an ordered sequence and the label is
defined relative to the *following* shift, shuffling rows lets a model train on shifts
that occur after the ones it is tested on. This note quantifies that effect.

Under random stratified 10-fold cross-validation, a class-weighted logistic regression
reaches ROC-AUC 0.755 and PR-AUC 0.195. Under time-ordered expanding-window validation,
the same model reaches ROC-AUC 0.668 and **PR-AUC 0.084** — a 57 % relative loss in
PR-AUC. A bagged CART ensemble shows the same pattern more strongly (PR-AUC 0.222 →
0.078, −65 %). Adding the record index — a pure time proxy carrying no physical
information — *improves* random-CV scores (CART PR-AUC 0.222 → 0.281) while *degrading*
time-ordered scores (0.085), which is the signature of temporal leakage. On a single
chronological holdout (train on the first 70 % of records, test on the last 30 %), both
models fall to ROC-AUC 0.57–0.61 and recall 0.115 at an operational threshold.

**Conclusion.** For this dataset, random cross-validation is optimistic, and the
optimism is not a property of one model family. The record index alone achieves
ROC-AUC 0.670, matching the full 17-feature model's *honest* temporal performance,
because the label prevalence drifts by a factor of ~7 across the record sequence.
Any claim about the forecasting skill of these models should be based on
time-respecting validation.

## 1. Introduction

Seismic-bump forecasting is a rare-event prediction problem: the consequences of a
missed event are severe, so the operating point matters more than aggregate accuracy.
The dataset's original study (Sikora & Wrobel, 2010) reports results obtained with
*stratified 10-fold cross-validation repeated 10 times*, and a widely used public
reproduction of that analysis follows the same protocol.

For a task framed as "given the previous shift, will the next shift be hazardous?",
stratified *k*-fold is not a valid estimate of forecasting skill, because it breaks the
temporal order of the sequence. Three distinct mechanisms can inflate the score:

1. **Chronological leakage** — training rows may post-date test rows.
2. **Distribution drift** — the label prevalence changes over the record (Section 4.1).
3. **Duplicate or near-duplicate records** — reduced here by de-duplication, but a
   general risk with shift-level monitoring data.

This note isolates mechanism (1)–(2) on a fixed dataset and two model families, and
reports the magnitude of the discrepancy.

## 2. Data

* 2,578 shift records (8 h each), 17 features used, binary target `class`.
* 170 positives → prevalence **6.59 %**.
* Source: UCI "seismic-bumps" (Sikora & Wrobel, 2010). The mirror used here has 2,578
  rows after removing 6 exact duplicates from the 2,584-row original; the positive
  count is unchanged at 170. Results are therefore comparable in size but not
  row-for-row with the original file.

**Integrity checks** (`results/integrity.json`):

| check | result | implication |
|---|---|---|
| duplicate rows | 0 | — |
| constant columns | `nbumps6`, `nbumps7`, `nbumps89` | zero information; they add pure noise dimensions |
| rank of `nbumps2…nbumps89` | 4 of 7 | exactly 3 linear dependencies, caused by the 3 constant columns |
| `nbumps` vs sum of range columns | equal in 2,576 / 2,578 rows | `nbumps` is a total; it is dropped to restore full rank |

The three constant columns explain the `(3 not defined because of singularities)`
message that appears when a full logistic-regression model is fitted to all 18
original features: the design matrix is rank-deficient by exactly three.

**Label drift across the record sequence** — prevalence by quintile of record order:

| quintile | 1st | 2nd | 3rd | 4th | 5th |
|---|---|---|---|---|---|
| P(hazardous) | **0.1609** | 0.0680 | 0.0213 | 0.0447 | 0.0349 |

The first fifth of the record is ~7.5× more hazardous than the third fifth. Whatever
its cause — a period of more intense mining, or a change of longwall — this structure
is what random cross-validation exploits.

## 3. Methods

### 3.1 Models

Both are implemented from scratch in NumPy (`src/models.py`) so that every reported
number is traceable.

* **Logistic regression**, L2-regularised (λ = 1.0 on standardised features),
  fitted by iteratively reweighted least squares, with class weights
  `n / (2·n_pos)` and `n / (2·n_neg)`. The intercept is unpenalised.
* **Bagged CART**, 60 bootstrap trees, depth 6, minimum 20 samples per leaf, Gini
  impurity, candidate splits at 12 quantiles per feature. Included so that the
  conclusion is not an artefact of a linear model.

Feature standardisation is fitted **inside** each training fold only. Scaling on the
full dataset before cross-validation would introduce a second, subtler leak.

### 3.2 Validation schemes (`src/evaluation.py`)

| scheme | description | models the task? |
|---|---|---|
| Random stratified 10-fold | rows shuffled, class ratio preserved per fold; averaged over 5 seeds | no |
| Time-ordered expanding window | 5 blocks; fold *i* trains on blocks 1…*i*, tests on block *i*+1 | yes |
| Chronological holdout | single split: first 70 % train, last 30 % test | yes |

### 3.3 Metrics (`src/metrics.py`)

Accuracy alone is uninformative here: predicting "no hazard" for every record already
scores **0.9341**. We therefore report ROC-AUC, PR-AUC (average precision), balanced
accuracy, and recall/precision at a threshold that flags the riskiest 6.59 % of shifts
— the operating point implied by the base rate.

## 4. Results

### 4.1 Model × validation scheme

| model | validation | ROC-AUC | PR-AUC | accuracy | balanced acc. | recall |
|---|---|---|---|---|---|---|
| Logistic regression | random stratified 10-fold | 0.755 (sd 0.004) | 0.195 (sd 0.003) | 0.904 | 0.610 | 0.271 |
| Logistic regression | time-ordered expanding | 0.668 | **0.084** | 0.927 | 0.555 | 0.148 |
| Bagged CART | random stratified 10-fold | 0.774 (sd 0.003) | 0.222 (sd 0.008) | 0.902 | 0.603 | 0.259 |
| Bagged CART | time-ordered expanding | 0.640 | **0.078** | 0.924 | 0.537 | 0.114 |

Two observations:

* The **ranking of the models reverses** between schemes. Under random CV the
  non-linear ensemble looks better (0.774 vs 0.755, PR-AUC 0.222 vs 0.195); under
  time-ordered validation it is worse (0.640 vs 0.668). A more flexible model exploits
  the leaked structure more effectively and collapses further when it is removed.
* The loss is much larger in **PR-AUC** (−57 % and −65 %) than in ROC-AUC (−12 % and
  −17 %). For a rare-event problem, PR-AUC is the more relevant summary, so random CV
  overstates skill most in the metric that matters most.

The published baseline table for this dataset reports accuracy and balanced accuracy
only; it does not report ROC-AUC or PR-AUC, so a direct metric-for-metric comparison
is not possible. Balanced accuracies there (50–69 %) bracket those obtained here
(54–61 %), which is consistent with our models being of comparable quality rather
than better.

### 4.2 Leakage probe

The record index (scaled to [0, 1]) is appended as an 18th feature. It carries no
physical information.

| model | validation | ROC-AUC | PR-AUC |
|---|---|---|---|
| Logistic regression | random stratified 10-fold | 0.762 | 0.206 |
| Logistic regression | time-ordered expanding | 0.609 | 0.063 |
| Bagged CART | random stratified 10-fold | **0.804** | **0.281** |
| Bagged CART | time-ordered expanding | 0.669 | 0.085 |

Adding a pure time proxy **raises** random-CV PR-AUC for the CART ensemble from 0.222
to 0.281 (+27 %) while leaving honest temporal performance essentially unchanged. This
is the diagnostic signature of temporal leakage and it is the clearest single piece of
evidence in this study.

**Univariate reference.** Using the negated record index alone as a score gives
ROC-AUC **0.670**. That single, physically meaningless variable matches the full
17-feature model's honest time-ordered performance (0.668).

### 4.3 Chronological holdout

Training on the first 70 % of records and testing on the last 30 % (n = 774):

| model | ROC-AUC | PR-AUC | accuracy | balanced acc. | recall | precision |
|---|---|---|---|---|---|---|
| Logistic regression | 0.568 | 0.090 | 0.941 | 0.542 | 0.115 | 0.115 |
| Bagged CART | 0.612 | 0.087 | 0.941 | 0.542 | 0.115 | 0.115 |

On a genuine future holdout the models are close to uninformative (ROC-AUC 0.57–0.61).
The high accuracy (0.941) is achieved by predicting "no hazard" almost always, which is
exactly the failure mode that aggregate accuracy conceals.

### 4.4 Feature importance

Permutation importance (drop in ROC-AUC when a column is shuffled), bagged CART fitted
on all records, in-sample ROC-AUC 0.899, 5 repeats:

| rank | feature | AUC drop | sd |
|---|---|---|---|
| 1 | `nbumps2` (bumps in 10²–10³ J) | 0.0645 | 0.0051 |
| 2 | `gpuls` | 0.0562 | 0.0040 |
| 3 | `energy` | 0.0522 | 0.0043 |
| 4 | `genergy` | 0.0431 | 0.0027 |
| 5 | `gdenergy` | 0.0291 | 0.0021 |
| 6 | `gdpuls` | 0.0219 | 0.0031 |
| 7 | `shift` | 0.0099 | 0.0018 |
| 8 | `nbumps3` | 0.0094 | 0.0018 |
| 9 | `maxenergy` | 0.0088 | 0.0007 |
| 10 | `seismoacoustic` | 0.0041 | 0.0008 |

The signal is dominated by low-energy bump counts and by the previous shift's
geophone energy and pulse count. The categorical hazard assessments
(`seismoacoustic`, `ghazard`) contribute little on top of the continuous monitoring
channels — an observation worth checking against a model with explicit mechanism
constraints, since permutation importance on correlated features understates the
importance of each member of a correlated group.

## 5. Discussion

1. **Random CV is optimistic on this dataset, and the optimism is model-independent.**
   The effect appears in both a linear and a non-linear model, and is larger for the
   more flexible one.

2. **The reported skill of a rare-event forecasting model is highly sensitive to the
   validation protocol.** Here the same model spans "useful" (ROC-AUC 0.77) to "barely
   better than chance" (0.57) depending only on how the data are split. Since the
   operational purpose is early warning, the honest number is the lower one.

3. **A rank-deficient design matrix was present in the original feature set.** Three of
   the 18 columns are constant and three linear dependencies exist among the bump-range
   counts. This does not damage tree-based models but makes unregularised logistic
   coefficients uninterpretable and produces the well-known "singularities" warning.

4. **The drift structure is itself informative.** A ~7.5× change in base rate across
   the record is not noise; it suggests the record spans distinct mining conditions.
   A model that appears to generalise across them under random CV may simply be
   memorising which regime each row belongs to.

---

## 6. Limitations

* The dataset has no explicit timestamp. Row order is treated as the chronological
  order of shifts, as described in the source documentation. If rows are instead
  grouped by longwall, the same argument applies with "group" in place of "time": a
  random split still violates the independence assumption, so the conclusion holds
  either way. The precise magnitude of the drop may differ.
* Two longwalls are present but cannot be separated, as no wall identifier is provided.
* No hyper-parameter search was performed. Tuning was deliberately avoided so that the
  comparison between validation schemes is not confounded by model selection; light
  tuning would raise all numbers but should not remove the gap.
* The published baselines report different metrics (accuracy, balanced accuracy), so
  only qualitative comparison is possible.
* Permutation importance on correlated features understates individual contributions.

